# V-LiSEMOD Documentation

This `docs/` folder keeps detailed technical, maintenance, and manuscript-facing material out of the public landing page while preserving a GitHub-friendly documentation map.

## Documentation Index

| File | Purpose |
|---|---|
| [APP_GUIDE.md](APP_GUIDE.md) | Public-facing explanation of the main app modules and how to interpret each page |
| [DATABASE.md](DATABASE.md) | Database layers, key tables, generated assets, and public-repo data handling notes |
| [PROTACABILITY.md](PROTACABILITY.md) | Careful interpretation guidance for the PROTACability workflow and outputs |
| [DEPLOYMENT.md](DEPLOYMENT.md) | Local run, environment variables, deployment pathways, and operational pitfalls |
| [MAINTENANCE.md](MAINTENANCE.md) | Cache cleanup, generated folders, repo hygiene, and pre-push checks |
| [DEVELOPER_NOTES.md](DEVELOPER_NOTES.md) | Flask structure, route inspection, template conventions, and developer caveats |
| [MANUSCRIPT_OUTLINE.md](MANUSCRIPT_OUTLINE.md) | Scientific framing scaffold for manuscript or software-note development |

## Suggested Reading Order

1. Start with [APP_GUIDE.md](APP_GUIDE.md) for product-level orientation.
2. Use [PROTACABILITY.md](PROTACABILITY.md) before describing degrader-readiness outputs publicly.
3. Use [DATABASE.md](DATABASE.md), [DEPLOYMENT.md](DEPLOYMENT.md), and [MAINTENANCE.md](MAINTENANCE.md) for implementation and operational work.
4. Use [DEVELOPER_NOTES.md](DEVELOPER_NOTES.md) when changing routes, templates, or optional module behavior.
5. Use [MANUSCRIPT_OUTLINE.md](MANUSCRIPT_OUTLINE.md) for publication-facing narrative development.
